# نشر TeamUp على Render

هذا الدليل خاص بنشر نسخة Render منفصلة عن تشغيل Docker Compose المحلي. في Render سيتم نشر الواجهة كـ Static Site، والـ API كـ Docker Web Service، وقاعدة البيانات كـ PostgreSQL.

## الخدمات التي ينشئها Render

- `teamup-frontend`: ملفات HTML وCSS وJavaScript من مجلد `frontend`.
- `teamup-api`: تطبيق Node.js وExpress وSocket.IO باستخدام `backend/Dockerfile`.
- `teamup-db`: قاعدة PostgreSQL.

ملف `render.yaml` يعرّف الخدمات الثلاث. لا يتم تشغيل Nginx داخل Render؛ خدمة Static Site تتولى تقديم ملفات الواجهة. ملف Docker Compose يظل مخصصًا للتشغيل المحلي.

## قبل النشر

1. ارفعي آخر نسخة من ملفات المشروع إلى GitHub بعد فك ضغط النسخة المعدلة.
2. تأكدي أن ملف `.env` غير موجود في GitHub. ارفعي `.env.example` فقط عند الحاجة.
3. لا تضعي كلمات مرور أو مفاتيح سرية داخل `frontend/config.js` أو أي ملف Frontend.

## خطوات النشر

1. افتحي https://render.com وسجلي الدخول باستخدام GitHub.
2. من Dashboard اختاري **New +** ثم **Blueprint**.
3. اختاري Repository الخاص بمشروع TeamUp، ثم اختاري الفرع `main` واضغطي Deploy.
4. وافقي على إنشاء الخدمات المعرفة في `render.yaml`.
5. انتظري حتى تنتهي عملية بناء `teamup-api` و`teamup-frontend` وإنشاء قاعدة البيانات.

إذا طلب Render قيمة `FRONTEND_URL` أثناء إنشاء Blueprint ولم يكن رابط الواجهة معروفًا بعد، يمكن إدخال الرابط بعد الإنشاء من إعدادات Environment في خدمة `teamup-api`.

## ربط الواجهة بالـ API

1. افتحي خدمة `teamup-api` في Render وانسخي رابطها، مثل `https://teamup-api.onrender.com`.
2. افتحي الملف `frontend/config.js` في المشروع.
3. ضعي رابط الـ API مكان القيمة الفارغة، من دون `/` في نهاية الرابط:

   ```js
   window.TEAMUP_API_URL = 'https://YOUR-API.onrender.com';
   ```

4. احفظي التعديل واعملي Commit وPush إلى GitHub. سيعيد Render نشر Static Site تلقائيًا إذا كان Auto-Deploy مفعّلًا.
5. افتحي خدمة `teamup-frontend` وانسخي رابطها.
6. في خدمة `teamup-api` افتحي **Environment** واضبطي `FRONTEND_URL` على رابط الواجهة بالضبط، مثل `https://teamup-frontend.onrender.com`، ثم احفظي التغييرات ليعاد نشر الـ API.

## قاعدة البيانات

يقرأ الـ API ملف `db/init.sql` عند بدء التشغيل وينشئ الجداول التي لم تُنشأ من قبل. أوامر الإنشاء تستخدم `IF NOT EXISTS` حتى لا تحذف بيانات موجودة عند إعادة التشغيل. متغير `DATABASE_URL` يُربط تلقائيًا بقاعدة Render المعرفة في `render.yaml`.

## إعداد تخزين الملفات والصور

Render Blueprint لا ينشئ خدمة MinIO في هذا الإعداد. لذلك ستعمل صفحات الطلاب والمشاريع والمهام والمحادثة بعد ضبط قاعدة البيانات، لكن رفع الملفات والصور لن يعمل حتى تضبطي خدمة تخزين متوافقة مع MinIO/S3.

بعد توفير خدمة تخزين متوافقة، أضيفي المتغيرات التالية إلى Environment في `teamup-api`:

- `MINIO_ENDPOINT`: اسم المضيف فقط، من دون `https://`.
- `MINIO_PORT`: غالبًا `443` عند استخدام HTTPS، أو المنفذ الذي يحدده مزود التخزين.
- `MINIO_USE_SSL`: `true` عند استخدام HTTPS.
- `MINIO_USER`: Access Key.
- `MINIO_PASSWORD`: Secret Key.
- `MINIO_BUCKET`: `teamup`.

يجب أن تسمح بيانات التخزين بالتحقق من الـ bucket وإنشائه أو أن يكون الـ bucket موجودًا مسبقًا. لا تضعي بيانات التخزين في ملفات GitHub.

## الاختبار

1. افتحي `https://YOUR-API.onrender.com/health` وتأكدي من ظهور `ok: true` و`database: connected`.
2. افتحي رابط الواجهة.
3. أنشئي حسابًا تجريبيًا وسجلي الدخول.
4. جرّبي إنشاء مشروع وإضافة مهارات وإرسال طلب انضمام.
5. جرّبي المحادثة بعد تسجيل الدخول بعضوين مختلفين وانضمامهما إلى نفس المشروع.
6. اختبري رفع الملفات بعد إعداد التخزين الخارجي فقط.

## ملاحظات مهمة

- الخطة المجانية قد تجعل خدمة الويب تدخل في وضع الخمول بعد عدم الاستخدام؛ أول طلب بعدها قد يستغرق وقتًا أطول.
- قواعد بيانات Render المجانية لها قيود ومدة صلاحية؛ راجعي تفاصيل الخطة الحالية قبل الاعتماد عليها في عرض نهائي.
- لا تستخدمي بيانات طلاب حقيقية أو كلمات مرور حقيقية أثناء التجربة العامة.
- احتفظي بنسخة احتياطية من قاعدة البيانات قبل أي تغيير أو إعادة إنشاء للخدمة.
