# دليل مشروع Teamup — شرح وتجهيز للمناقشة

## 1. فكرة المشروع

Teamup منصة ويب تساعد طلاب الجامعة على تكوين فرق للمشروعات الجامعية. الطالب ينشئ ملفًا شخصيًا ويضيف مهاراته، ثم يستطيع استعراض المشروعات المفتوحة أو رؤية المشروعات التي تتوافق مهاراتها المطلوبة مع مهاراته. يمكنه إرسال طلب انضمام، ويستطيع مالك المشروع قبول الطلب أو رفضه.

بعد الانضمام، يستطيع أعضاء الفريق إدارة المهام، وتبادل الرسائل الفورية، ورفع ملفات المشروع.

## 2. المشكلة التي يعالجها المشروع

قد يواجه الطالب صعوبة في العثور على زملاء يمتلكون المهارات المطلوبة لمشروع معين. كما قد تكون متابعة المهام والملفات والمحادثات موزعة على أدوات مختلفة. يجمع Teamup هذه الأنشطة في منصة واحدة.

## 3. المستخدمون والأدوار

- **الطالب:** ينشئ حسابًا، ويضيف مهاراته، ويتصفح المشروعات، ويرسل طلبات الانضمام.
- **مالك المشروع:** ينشئ المشروع، ويحدد حجم الفريق والمهارات المطلوبة، ويتعامل مع طلبات الانضمام.
- **عضو الفريق:** يشارك في محادثة الفريق، ويتابع المهام، ويصل إلى ملفات المشروع.

مالك المشروع عضو في الفريق أيضًا، وتُسجل عضويته بدور `owner`.

## 4. التقنيات المستخدمة

| التقنية | الاستخدام |
|---|---|
| HTML / CSS / JavaScript | بناء واجهة المستخدم |
| Node.js | تشغيل بيئة JavaScript على الخادم |
| Express | إنشاء REST API |
| PostgreSQL | حفظ المستخدمين والمشروعات والمهام والرسائل |
| JWT | التحقق من هوية المستخدم في طلبات API وSocket.IO |
| bcryptjs | تخزين كلمات المرور بصيغة hash |
| Socket.IO | المحادثات والإشعارات الفورية |
| MinIO | تخزين صور المشروعات والملفات |
| Nginx | تقديم الواجهة وتحويل طلبات API وSocket.IO إلى الخادم |
| Docker Compose | تشغيل الخدمات معًا |

## 5. معمارية النظام

1. المتصفح يعرض ملفات `frontend/index.html`.
2. طلبات `/api` تمر عبر Nginx إلى تطبيق Express.
3. Express يتحقق من JWT ثم ينفذ الاستعلامات على PostgreSQL.
4. صور المشروعات والملفات تحفظ في MinIO، وتُسجل بياناتها في PostgreSQL.
5. Socket.IO يتعامل مع الرسائل والإشعارات الفورية.
6. Docker Compose يشغل PostgreSQL وMinIO وAPI وNginx.

## 6. شرح تدفق الاستخدام

### إنشاء حساب
يرسل المستخدم الاسم والبريد وكلمة المرور. يتحقق الخادم من البيانات، ويستخدم bcrypt لتخزين hash لكلمة المرور، ثم يعيد JWT بعد نجاح التسجيل.

### إنشاء مشروع
يحدد المالك عنوان المشروع والوصف والمقرر وحجم الفريق والمهارات المطلوبة. يُضاف المالك تلقائيًا إلى جدول أعضاء المشروع.

### المطابقة
يقارن النظام مهارات المستخدم بمهارات المشروع المطلوبة. يحسب نسبة المهارات المتطابقة إلى إجمالي المهارات المطلوبة، ويعرض المشروعات ذات التطابق الأكبر أولًا. هذه مطابقة مباشرة للمهارات المسجلة وليست نموذج ذكاء اصطناعي.

### طلب الانضمام
يرسل الطالب طلبًا إلى المشروع المفتوح. يظهر الطلب لمالك المشروع، الذي يمكنه قبوله أو رفضه. عند القبول يتحقق الخادم من أن المشروع ما زال مفتوحًا وأن هناك مكانًا متاحًا، ثم يضيف العضو داخل معاملة قاعدة بيانات.

### المهام
يمكن لأعضاء المشروع إضافة مهمة وتعيينها إلى عضو في الفريق وتغيير حالتها إلى `todo` أو `doing` أو `done`.

### المحادثة والملفات
يتحقق Socket.IO من هوية المستخدم وعضويته قبل السماح له بدخول غرفة المشروع. ملفات المشروع لا يمكن تنزيلها إلا بواسطة عضو في المشروع.

## 7. قاعدة البيانات

- `users`: بيانات الطلاب وكلمات المرور المشفرة.
- `skills`: قاموس المهارات.
- `user_skills`: ربط الطلاب بمهاراتهم.
- `projects`: بيانات المشروعات ومالك المشروع وحجم الفريق والحالة.
- `project_skills`: المهارات المطلوبة لكل مشروع.
- `members`: أعضاء كل فريق وأدوارهم.
- `join_requests`: طلبات الانضمام وحالتها.
- `tasks`: مهام المشروع والمسؤول عنها وحالتها.
- `messages`: رسائل المحادثة.
- `project_files`: بيانات الملفات المخزنة في MinIO.

### أهم العلاقات

- المستخدم يمكن أن يمتلك عدة مشروعات.
- المستخدم يمكن أن ينضم إلى عدة مشروعات من خلال `members`.
- المشروع يمكن أن يحتوي على عدة مهارات مطلوبة.
- المشروع يمكن أن يحتوي على عدة طلبات انضمام ومهام ورسائل وملفات.
- المهارات ترتبط بالمستخدمين والمشروعات بعلاقات many-to-many.

## 8. نقاط الأمان التي تم تحسينها

- عدم تشغيل التطبيق دون `JWT_SECRET` قوي.
- استخدام bcrypt لتخزين كلمات المرور.
- التحقق من صلاحية المستخدم قبل الوصول إلى API.
- التحقق من عضوية الفريق قبل الوصول إلى ملفات المشروع أو غرفة المحادثة.
- التحقق من أن الشخص المعيّن للمهمة عضو في المشروع.
- منع قبول أعضاء بعد امتلاء الفريق، مع قفل سجل المشروع أثناء قرار القبول.
- إضافة قيود في قاعدة البيانات لأحجام الفرق والحالات المسموح بها.
- تحديد الحد الأقصى لحجم الملف المرفوع بـ20 MB.

## 9. سيناريو العرض العملي المقترح

1. إنشاء حساب طالب أول وإضافة مهارات مثل Python وUI/UX.
2. إنشاء مشروع يحتاج Python وUI/UX وتحديد حجم الفريق.
3. تسجيل الدخول بحساب طالب ثانٍ يمتلك إحدى المهارات المطلوبة.
4. فتح صفحة For you وملاحظة ظهور المشروع في قائمة المطابقة.
5. إرسال طلب انضمام.
6. العودة لحساب مالك المشروع وقبول الطلب.
7. فتح المشروع بحساب العضو الجديد وإضافة مهمة وتعيينها لأحد أعضاء الفريق.
8. إرسال رسالة في المحادثة.
9. رفع ملف تجريبي والتأكد من ظهوره لأعضاء الفريق.

## 10. حدود النسخة الحالية

- المطابقة تعتمد على تطابق أسماء المهارات المسجلة، ولا تستخدم تعلم الآلة.
- الإشعارات الفورية تظهر داخل جلسة التطبيق، ولا يوجد تكامل بريد إلكتروني أو إشعارات هاتف.
- لا توجد لوحة إدارة مستقلة للمشرف.
- هذه نسخة عرض محلية، وليست إعدادًا مكتملًا للنشر العام على الإنترنت.
