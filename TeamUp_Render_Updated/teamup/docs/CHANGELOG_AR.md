# ملخص التعديلات على نسخة Teamup

هذه التعديلات أُجريت على ملفات المشروع المرفوعة، مع الحفاظ على فكرة التطبيق وبنيته الأساسية.

## Backend والأمان
- جعل `JWT_SECRET` مطلوبًا بدل استخدام قيمة افتراضية ضعيفة.
- تقليل مدة صلاحية JWT إلى 12 ساعة.
- رفع متطلبات كلمة المرور الجديدة إلى 8–72 حرفًا واستخدام bcrypt cost factor أعلى.
- نقل مسار الملفات خلف التحقق من تسجيل الدخول.
- قصر تنزيل ملفات المشروع على أعضاء الفريق، مع السماح للمستخدم المسجل بمشاهدة صور أغلفة المشروعات.
- إرسال الملفات كمرفقات افتراضيًا، والسماح بعرض صور محددة فقط.
- التحقق من صلاحية الشخص المعيّن للمهمة ومن حالات المهام.
- التحقق من حجم الفريق والمهارات والعناوين والمدخلات الأساسية.
- جعل إنشاء المشروع وتحديث الملف الشخصي وقبول طلب الانضمام عمليات تستخدم معاملات قاعدة البيانات.
- تحسين معالجة أخطاء Socket.IO ومهام التذكير.

## قاعدة البيانات
- إضافة قيود لأحجام الفرق وحالات المشروعات والطلبات والمهام.
- إضافة فهارس لطلبات الانضمام والمشروعات.
- توثيق أن ملف schema يعمل تلقائيًا عند إنشاء volume جديد فقط.

## التشغيل والتوثيق
- إضافة `.env.example` و`.gitignore`.
- تحديث Docker Compose لاستخدام أسرار مطلوبة بدل كلمات مرور افتراضية.
- تشغيل API بمستخدم Node غير root داخل الحاوية.
- إضافة فحص صحة API وقاعدة البيانات.
- توسيع README وإضافة دليل المشروع وأسئلة المناقشة وقائمة الاختبار.

## ما تم التحقق منه
- اجتازت ملفات JavaScript الخاصة بالـBackend فحص `node --check`.
- اجتاز JavaScript المضمن في الواجهة فحص `node --check`.
- لم يتم تنفيذ اختبار تكاملي فعلي عبر Docker أو PostgreSQL في بيئة إعداد هذه الحزمة؛ لذلك يجب تنفيذ قائمة الاختبارات في `TEST_CHECKLIST_AR.md` على اللابتوب قبل العرض.

## تجهيز النشر على Render
- دعم `PORT` الذي توفره منصة الاستضافة بدل تثبيت المنفذ 3000.
- إضافة CORS للـ HTTP وSocket.IO مع تحديد رابط الواجهة من `FRONTEND_URL`.
- فصل عنوان الـ API في `frontend/config.js` لدعم نشر الواجهة والـ API على رابطين مختلفين.
- جعل إعداد SSL لتخزين MinIO قابلًا للضبط من متغيرات البيئة.
- جعل إنشاء جداول قاعدة البيانات آمنًا عند إعادة التشغيل باستخدام `IF NOT EXISTS`.
- إضافة `render.yaml` ودليل نشر عربي.
